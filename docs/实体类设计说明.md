## 一、总规范（14 个实体统一遵守）

### 1.1 命名映射规则（驼峰 ↔ 下划线）

| 层 | 规则 | 示例 |
|---|---|---|
| 表名 ↔ 类名 | 下划线 ↔ 大驼峰 | `show_info` ↔ `ShowInfo`、`orders` ↔ `Orders`、`audit_log` ↔ `AuditLog` |
| 列名 ↔ 属性名 | 下划线 ↔ 小驼峰 | `id_card_no` ↔ `idCardNo`、`sale_start_time` ↔ `saleStartTime` |

MP 的 `map-underscore-to-camel-case: true`（application.yml 已配）负责**列名↔属性名**的自动映射；表名的自动映射 MP 也支持（类名驼峰转下划线），但我们**显式写 `@TableName`**——防御性声明，类名重构时映射不断。

### 1.2 类注解统一五件套（所有实体相同）

```java
@Data                          // getter/setter/toString/equals/hashCode
@NoArgsConstructor             // 无参构造：MP/MyBatis 反射装配必需
@AllArgsConstructor            // 全参构造：顶掉了默认无参构造，故上面的 @NoArgsConstructor 必须成对出现
@Builder                       // 链式构建（已批准）：手动造对象/测试更可读
@TableName("表名")             // 显式声明表映射
public class Xxx implements Serializable {
    private static final long serialVersionUID = 1L;   // 数据载体全族统一声明
    ...
}
```

**@Builder 的注意点**：它会生成一个全参构造并顶掉默认无参构造，所以 @NoArgsConstructor 必须并存（三件套原则不变）；Lombok 的 @Builder 用在类上时要求所有字段都有初始值处理，与 @NoArgsConstructor 共存需依赖 @AllArgsConstructor 撑住全参路径——这套组合是经过验证的标准搭配。

### 1.3 类型映射表（SQL ↔ Java）

| SQL 类型 | Java 类型 | 示例字段 |
|---|---|---|
| BIGINT | Long | id、user_id、merchant_id |
| VARCHAR / TEXT | String | phone、detail、callback_body |
| TINYINT | Integer | status、pool_type、vip_level |
| INT | Integer | stock、points、version |
| DECIMAL(10,2) | BigDecimal | price、amount、pay_amount |
| DATETIME | LocalDateTime | session_time、expire_time、create_time |

### 1.4 纪律

- 实体**只做表映射**：不写业务方法、不加数据库不存在的展示字段（statusDesc/venueName 等 belongs to VO）、不加 `@TableField(exist = false)`；
- 状态字段类型是 `Integer`（存数字），枚举只做业务层的语义包装和翻译；
- `serialVersionUID` 手写声明，值统一 `1L`（@Data 不生成它）。

## 二、公共注解详解（谁处理它、为什么这么标）

| 注解 | 标在哪 | 作用 | 处理者 |
|---|---|---|---|
| `@TableName("orders")` | 类上 | 声明实体 ↔ 表映射 | MP 生成 SQL 时定位表 |
| `@TableId(type = IdType.AUTO)` | id | 主键 + 数据库自增回填：insert 后 MP 把自增 id 写回实体 | MP |
| `@TableField(fill = FieldFill.INSERT)` | createTime、createUser | 插入时自动填充 | AuditMetaObjectHandler.insertFill |
| `@TableField(fill = FieldFill.INSERT_UPDATE)` | updateTime、updateUser | 插入和更新时自动填充 | AuditMetaObjectHandler（insert/update 两个方法） |
| `@Version` | SessionCategoryStock.version | 乐观锁：UPDATE 自动拼 `version=version+1 WHERE version=旧值` | MybatisPlusConfig 的乐观锁插件 |
| `implements Serializable` | 类上 | 数据载体零成本保险（原生序列化场景） | JVM |

**审计四字段在每个实体的完整写法**（AuditLog 例外见下）：

```java
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;
@TableField(fill = FieldFill.INSERT)
private Long createUser;
@TableField(fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
@TableField(fill = FieldFill.INSERT_UPDATE)
private Long updateUser;
```

## 四、审核结论（已全部确认）

1. ✅ SessionCategoryStock.version 标 @Version——全项目唯一乐观锁实体（v1.5：库存主体从票档移到"场次×票档"交叉表；orders 状态流转用条件更新 CAS，不需要 version 列）；
2. ✅ AuditLog 只有 createTime——只追加表，strictFill 的 null 跳过语义天然兼容；
3. ✅ 状态字段全部 Integer 存数字，枚举只做翻译器；
4. ✅ OrderItem 无 quantity——一行一个票位（v1.3 决议）；
5. ✅ 实体统一加 @Builder（五件套：@Data/@NoArgs/@AllArgs/@Builder）；
6. ✅ 全部实现 Serializable + serialVersionUID=1L。
