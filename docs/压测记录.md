## 二、B 组：Redis 结果缓存（分层策略）

时间：2026-11-21 23:40（预热后压测）

**策略**：无 keyword 且 pageNum ≤ 50 → 走 Redis 结果缓存（TTL 30~59s 抖动）；**带 keyword 或深页（pageNum > 50）→ 不缓存，直查 DB**（长尾不进缓存，P6 交 ES）。

| 场景 | 请求数 | QPS | 平均耗时 | P95 | 错误 |

| 默认列表（无 keyword，**缓存命中**）| 1000 | **1966.8** | 25.4 ms | **42.1 ms** | 0 |
| keyword 搜索（**不走缓存**，直查 LIKE）| 1000 | 1648.8 | 39.0 ms | 65.7 ms | 0 |

**对比 A 组（直查：754.0 / 117.1ms / 780.4ms）**：

| 场景 | QPS 变化 | P95 变化 |
|---|---|---|
| 默认列表（缓存命中）| **+161%** | **-95%**（780 → 42ms）|
| keyword 搜索（直查）| +119%* | -92%* |

> *注：keyword 场景与 A 组非同一时刻压测（MySQL Buffer Pool 已预热），横向对比仅供参考；其绝对性能（39ms/1649 QPS）已可接受，P6 由 ES 优化。

**功能验证（4/4）**：默认列表两次结果一致（命中缓存）✓；keyword 结果全部含关键词 ✓；深页 pageNum=51 正常返回 ✓；错误 0 ✓。
