# 云票 CloudTicket · 票务预订平台 项目大纲

> **定位**：面向演出场景的双端票务交易平台（主办方端 + 用户端），以"开售抢票"为核心高并发场景，会员双池权益与社区签到玩法为辅。
> **文档性质**：产品需求（轻量）+ 技术方案（重点）+ 迭代路线。原则：不纠结产品体验细节，一切模块为"让技术有真实场景"服务。
> **技术基线**：Java **21**（虚拟线程压测实验）/ Spring Boot **3.5.x**（不升 4.x：RocketMQ starter、Knife4j 等生态尚未适配，Boot 4 换 Jackson 3 迁移成本高，教程生态全在 3.x）/ Maven 多模块 / **MyBatis-Plus（单表）+ MyBatis XML（复杂 SQL）** / MySQL 8 / Redis 7 + Redisson + Caffeine / **RocketMQ 5.x** / Sentinel / WebSocket / EasyExcel / JMeter / Docker Compose / 支付宝沙箱 / Elasticsearch

## 一、角色与端结构（2 个前端应用 + 3 类角色 + 1 个系统侧）

| 应用 | 角色 | 核心职责 |
|---|---|---|
| 用户端 web-user（H5，AI 生成） | 普通用户 / 会员 | 浏览搜索、抢票下单、支付、票夹、退票、签到积分、社区讨论 |
| 管理端 web-admin（Vue3+Element Plus，AI 生成） | 主办方 | 演出/票档（双池配额）管理、批量导入、订单/核销、退票审核、销售统计、来单提醒 |
| （同上，按角色显隐菜单） | 平台管理员 | 主办方入驻审核、演出审核、全局看板、审计日志 |
| 系统侧（无界面，后端进程） | 定时任务 / MQ 消费者 | 开售流转、超时兜底、对账、异步出票与通知、播报采样 |

双端隔离沿用苍穹外卖方案：不同密钥、不同 header、不同拦截器。前端 CORS + Axios 统一封装（401 跳登录、业务错误弹提示）。

## 二、核心业务主干

```
主办方创建演出+票档（设置公开池/会员池配额）→ 提交审核 → 平台审核通过 → 开售时间自动流转
        ↓
用户浏览/搜索演出（缓存+ES）→ 添加观演人（姓名+证件）→ 开通会员（可选，虚拟商品订单）
        ↓
【抢票链路】Sentinel限流 → 防重token → Redis Lua 按身份路由双池扣减
        ├─ 会员：先扣会员池，不足转公开池；可买任何池
        └─ 普通用户：仅公开池；抢会员池 → 特定错误码拒绝
        + 实名限购（观演人证件判重）→ RocketMQ 异步落单 → DB条件更新扣对应池(防超卖)
        → 下单成功事件 → MQ → 限速采样 → WebSocket 抢票播报站广播
        ↓
订单待支付 —15分钟—→ RocketMQ 延迟消息取消 + 定时扫描兜底 + 回调竞态仲裁（三重保障）
        ↓
支付（支付宝沙箱，可用折扣券抵扣）→ 异步回调(验签+金额校验+幂等) → MQ 异步出票
        → WebSocket 主办方来单提醒 + 站内通知
        ↓
演出日：出示票码 → 核销（幂等：一票一核）
退票：退票规则(策略，会员免手续费+更长窗口) → 审核队列会员优先 → 支付宝退款
        → 票作废 + 库存按原池回补(order.pool_type) → 余票提醒已预约用户
        ↓
全程：本地消息表+每日对账 · 销量攒批统计 · traceId 可观测
侧线：签到(Bitmap)得积分 → 积分兑换折扣券 → 下单用券支付打折（服务端金额重算）
      讨论频道：发帖/点赞(Lua)/热帖榜(ZSet) · 演出评论区 · 开售提醒预约(延迟消息)
```

## 四、核心状态机

**演出**：`草稿 → 待审核 → 通过 → 销售中 → 已结束`；分支：驳回→草稿、下架。流转全部**条件更新 CAS**。
**订单**：`待支付 → 已支付(待出票) → 已出票 → 已核销 → 已完成`；分支：`待支付→已取消`、`已支付/已出票→退款中→已退款`、`VIP会员订单(虚拟商品，支付即生效)`。
**票**：`有效 → 已核销 / 已退款`。
**用户持券 user_coupon**：`未使用 → 已使用（下单核销 CAS）/ 已过期`。

## 七、关键技术方案细节

### 7.1 抢票链路（核心）
1. Sentinel 全局限流+用户维度限流+防重 token；
2. Lua 按身份路由：从 Redis 读用户会员标识 → 会员先扣会员池、不足转公开池；普通用户仅公开池，请求会员池返回专属错误码 → 校验限购（`limit:{sessionId}:{userId}`）→ **校验观演人证件未购**（`idcard:{sessionId}` Set 判重）→ 预扣对应池+记录；
3. RocketMQ 发订单消息，接口返回"排队中"；消费者事务内 `UPDATE ... WHERE stock>=n`（扣 order 对应池，影响行数=0 回补+标记失败）+ 插订单（order_no 唯一索引幂等）；
4. 下单成功事件入 MQ → 播报消费组限速采样（每秒最多 N 条）→ WebSocket 广播脱敏昵称；
5. 失败路径：按 pool_type 回补对应池+限购集合，死信+对账接续；
6. **取消/超时/退款回补**：一律按 `orders.pool_type` 回补原池，每日对账双池校准；
7. 超卖演进：悲观锁→乐观锁→Lua+条件更新。
8. 压测场景组：1000 并发抢 500 票（公开池 400+会员池 100）零超卖；普通用户抢会员池 100% 被拒；会员池耗尽后会员自动转公开池。

### 7.2 超时取消三重保障
主保障：RocketMQ 延迟消息（5.x 精确 15min；4.x 取近似档位更能体现兜底必要）；兜底一：每分钟扫描（CAS 防误关）；兜底二：支付回调发现已取消 → 反向 CAS 自动退款。

### 7.3 幂等清单
防重 token、支付回调（out_trade_no 唯一+状态短路+**金额校验**）、核销（票状态 CAS）、MQ 消费（biz_no 唯一）、退款（refund_no+支付宝退款单号）、**用券（user_coupon 状态 CAS + order 关联唯一）**、**积分兑换（Lua 原子扣积分+流水唯一键）**、签到（当日 Bitmap 位防重复积分）。

### 7.4 缓存策略
详情：Redis+逻辑过期+布隆+TTL 抖动；列表：短 TTL；分类树/配置：Caffeine；开售预热一次性灌入**双池库存+布隆过滤器+会员标识缓存**；库存一律 Lua 不走 Cache-Aside。

### 7.5 金额规则（铁律）
订单金额三段式：原价 → 券抵扣（discount_amount）→ 应付（pay_amount），**全部服务端重算，不信前端任何金额**；支付回调校验 `回调金额 == pay_amount`；退款按规则返还券（未过期）与积分（原路）。

### 7.6 可观测性
入口 Filter 生成 traceId→MDC→日志 pattern→MQ header 透传→AOP 耗时→内存指标（QPS/P95/错误率/命中率/消费延迟）；验证：人为制造 MQ 停机/慢 SQL/Redis 异常，traceId 复盘定位。
**虚拟线程实验**：压测开/关虚拟线程两组数据，观察瓶颈从线程数转移到连接池的过程。

### 7.7 AI 预留
`AiAssistantService` + `LocalRuleFaqImpl`（退票规则/演出信息检索）+ 对话表 + SSE 端点占位；演示方向：对演出评论区做"AI 观演总结"。

### 7.8 票码与扫码核销
**码内容设计**：二维码不放明文票信息，只放凭证串 `ticket_no + 时间戳 + HMAC-SHA256 签名`（密钥仅服务端持有）——防伪造（无密钥签不出）、防篡改（改动即验签失败）、防截图转用（**30s 动态刷新**，验签校验时间窗口 ±30s）。
**生成与渲染**：后端 Hutool `SecureUtil.hmacSha256` 签发凭证串（`QrCodeUtil`/ZXing 可直出 Base64 备用）；推荐只返回串，用户端前端用 qrcode 组件渲染并定时刷新（刷新只传字符串，省流量）。
**核销三通道**（web-admin）：① 输码（P1 兜底）；② USB 扫码枪（P1，本质键盘设备扫码即输入+回车，零额外开发）；③ 摄像头扫码（P4，html5-qrcode，生产必须 HTTPS）。
**核销链路**：凭证串 → 验签+时间窗口 → 解出 ticket_no → 归属校验（场次属于当前主办方，防跨商户核销）→ CAS `UPDATE ticket SET status=已核销 WHERE ticket_no=? AND status=有效` → rows=1 成功 / rows=0 返回具体原因（已核销/已退款/不存在）→ 审计留痕；交互默认"扫码→展示票信息→确认核销"两步。
**验证实验**：截图旧票码 31s 后核销被拒；同票重复核销第二次返回"已核销"；伪造凭证串验签失败；跨主办方核销被数据权限拦截。
**演进叙事**：P1 静态签名码 → P4 动态刷新码+摄像头扫码（与 JWT→Sa-Token、LIKE→ES 同款素材）。

## 八、六期迭代计划（总量约 10~12 周）

> 纪律：每期结束"可部署、可演示、至少一条 bullet"；验证实验当期做、数字当期记。

**P1 骨架与双端闭环（约 2 周）**：多模块工程；双端登录；场馆/演出/场次/票档（双池字段）/观演人 CRUD；审核状态机；观演指南字段；会员开通（虚拟订单）；普通下单（同步+乐观锁，走公开池）；订单/核销（票码 HMAC 签发+输码/扫码枪核销）；数据权限+审计；支付 mock。验证：状态机非法流转用例、越权用例、伪造票码/重复核销用例。

**P2 读优化与可观测（约 1.5 周）**：缓存三件套+多级缓存+预热；热榜；JMeter 基线；traceId+耗时统计；虚拟线程初试。验证：直查/单级/多级三组对比；删缓存重建互斥。

**P3 抢票高并发（约 2.5 周）**：Lua 双池路由秒杀全链路（实名限购）；RocketMQ 异步+条件更新兜底+按池回补；超时取消三重保障；幂等体系；支付宝沙箱真接入；虚拟线程对比压测。验证：1000 并发抢 500 票零超卖；普通用户抢会员池 100% 被拒；延迟消息丢失注入兜底恢复；回调与取消竞态用例；虚拟线程开关吞吐对比。

**P4 可靠性与实时（约 2~2.5 周）**：本地消息表+每日对账（双池校准）；优惠券全链路（发放→下单核销→金额重算→回调校验→退款返还）；退票权益（会员优先队列+退票费策略）；攒批统计；Sentinel 限流+降级；EasyExcel；WebSocket 来单+播报站（采样）；开售提醒；线程池；票码升级 30s 动态刷新+摄像头扫码（html5-qrcode，HTTPS）。验证：MQ 停机注入零丢失；用券后回调金额校验用例；截图旧票码核销被拒；限流前后 P95/错误率；10 万行导入耗时。

**P5 社区与玩法（约 1.5 周）**：帖子+点赞 Lua+热帖榜；演出评论区+敏感词；签到 Bitmap+积分流水；积分兑换折扣券。验证：点赞并发一致性；同日重复签到拦截；兑换重复点击只扣一次积分。

**P6 加分与交付（约 1.5 周）**：ES（演出+帖子，LIKE→ES 演进）；HLL/GEO（可选）；Sa-Token 替换；AI 预留；Docker Compose+Nginx 上线；README+压测报告+简历终稿。验证：LIKE vs ES 对比；线上可用性检查单。

**超期砍单顺序**：GEO/HLL → 社区 → 签到积分 → ES；核心抢票链路（P1-P3）绝不动。

## 十、减法清单（明确不做）

| 不做 | 理由 | 替代 |
|---|---|---|
| 图形化选座 | 前端黑洞 | 票档模式（区域+数量） |
| 微服务 | 当前阶段负资产 | 单体多模块，面试讲"怎么拆" |
| 拼团团购 | 成团状态机+库存叠加模型重，业务牵强 | 团体购票阶梯价（下单数量逻辑） |
| 积分抽奖 | 被"积分兑换折扣券"取代，更贴交易主链路 | 积分兑换商城（若想要可作可选模块） |
| 会员优先购 | 被"会员专属池"取代，双池模型技术含金量更高 | 会员专享池+退票权益 |
| 社区私信/关注/收藏 | 范围失控 | 帖子+点赞+热榜三件 |
| 候补队列全功能 | 复杂 | 退票后余票提醒（复用提醒设施） |
| VIP 多级体系 | 两级足够，权益落在双池+退票 | 普通/会员两级 |
| 真实短信/OCR | 资质成本 | 通知表+沙箱 |
| 多端小程序 | 时间黑洞 | H5+管理后台模板 |
| AI 真接入 | 非本期重点 | 接口+对话表+SSE 钩子 |
