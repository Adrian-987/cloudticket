# 会员系统设计（P1 空壳 → P3 权益）

> 对应大纲 3.1「账号 · 会员开通」与 P3「双池路由」。本文记录 **2026-11-20 讨论裁定**，是实现与契约的依据。
> P1 只做"身份 + 开通 + 查询"（空壳，无购票权益）；权益统一 P3 落地。

---

## 一、讨论裁定（2026-11-20）

| 议题 | 裁定 |
|---|---|
| 会员是否 P1 做 | **做，但只做空壳**（能开通、能看状态，买票无任何特权）|
| P3 权益范围 | **① 专享票池（双池） + ③ 会员价 + ④ 退票权益**（提前购/积分/等级/自动续费不做）|
| 退票权益节奏 | **方案 A**：P3 只做"权益规则定义"（策略类+配置），**P4 退票功能上线即生效** |
| 平台端看会员 | 用户分页体现会员属性（已有 vipLevel，补到期时间 + 会员筛选）|
| 平台端看会员订单 | **加** `GET /admin/vip/orders/page` |
| 会员归属 | 用户属性；**主办方不参与**（VIP 订单无主办方，天然不进主办方查询）|

## 二、P1 空壳范围（做什么 / 不做什么）

### 2.1 做

| 层 | 内容 |
|---|---|
| 表 | `orders.show_id / session_id / merchant_id` 改为可空（虚拟订单无演出/场次/主办方）|
| 用户端 | `GET /user/vip`（查状态+档位）、`POST /user/vip/orders`（开通虚拟订单）、支付复用 04 §2 |
| 平台端 | 07 §9 用户分页补 `vipExpireTime` + 请求补 `vipLevel`；**08 §3 新增 VIP 订单分页** |
| 业务 | 支付成功 → 订单直接"已完成(4)"；`user.vip_level=1`、`vip_expire_time` **续费叠加** |

### 2.2 不做（P3/P4/P5）

```
❌ 双池购买路由（P3）
❌ 会员价（P3）
❌ 退票权益（P3 定规则、P4 生效）
❌ 提前购 / 积分 / 等级体系 / 自动续费（不做）
```

---

## 三、P1 关键规则

| 规则 | 说明 |
|---|---|
| 虚拟订单 | `order_type=2(VIP)`；`show_id/session_id/merchant_id = NULL`；`pool_type=1`（占位无意义）|
| 状态流转 | 待支付(0) →（支付成功）→ **已完成(4)**（无出票/核销）|
| 过期 | 未支付 15 分钟过期（与普通订单同 `expire_time` 机制）|
| 生效 | 支付成功即生效，无审核 |
| 续费叠加 | 原到期在 future → 从原到期 +N 月；已过期 → 从 now +N 月 |
| 过期判断 | **惰性**：`vipLevel=1 且 vipExpireTime > now` 才算有效会员（不依赖定时任务改字段）|
| 档位 | 两档常量（不建套餐表）：`MONTH`(1 个月, 19.90) / `YEAR`(12 个月, 199.00) |

## 四、P3 权益设计（预留）

### ① 专享票池（双池路由）

- 字段已有：`ticket_category.member_stock / sold_member_count`；
- P3：下单按身份路由（会员先会员池、不足转公开池；普通仅公开池）+ Lua 原子扣减 + 限购；
- `orders.pool_type` 记录扣减池 → 取消/退票按池回补；
- 契约不变（`poolType` 不出现在入参，后端按身份判定）。

### ③ 会员价

- 表变：`ticket_category` 加 `member_price DECIMAL(10,2) NULL`（空 = 该档无会员价）；
- 下单：会员且 `member_price` 非空 → 按会员价计（服务端取价，不信前端）；
- 契约：06 票档保存/详情、03 余量/详情 增加 `memberPrice`。

### ④ 退票权益（方案 A）

- **P3 只做规则**：策略接口 `RefundFeeStrategy`（普通/会员两档：会员免手续费、退票窗口更长），会员优先队列排序规则；
- **P4 退票功能上线即生效**（退票申请/审核/退款）；
- 契约：04 §6 退票占位章节届时补全。

## 六、面试叙事（简历素材）

1. **订阅制交易**：会员开通复用订单/支付链路（订单类型扩展），不另造一套支付；
2. **状态一致性**：支付即生效 + 续费叠加 + 惰性过期（不依赖定时任务，读写都判 expire）；
3. **权益分层演进**：P1 空壳（身份）→ P3 双池路由（同步条件更新 → Lua 原子）+ 会员价 + 退票策略；
4. **数据隔离**：VIP 订单 `merchant_id=NULL`，主办方订单查询天然看不到（`WHERE merchant_id=?`）；
5. **平台监管边界**：平台看得到会员属性与会员订单（07），但不参与交易明细与权益发放。
