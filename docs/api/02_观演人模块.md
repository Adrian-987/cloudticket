# 云票接口文档 · 02 观演人模块

> 前缀 `/user/attendee`，需用户鉴权（Authorization: JWT）。观演人是实名限购的数据基础：一张票对应一个观演人证件。

## 1. 新增观演人

### 1.1 基本信息

> 请求路径：/user/attendee
>
> 请求方式：POST
>
> 接口描述：为当前登录用户新增一名观演人（姓名 + 证件号）

### 1.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注                       |
| -------- | ------ | -------- | -------------------------- |
| name     | string | 必须     | 姓名，2~50 位              |
| idCardNo | string | 必须     | 18 位身份证号（含校验位验证） |
| phone    | string | 非必须   | 联系电话                   |

请求参数样例：

```json
{
  "name": "陈晓翔",
  "idCardNo": "440103200501011234",
  "phone": "13800001234"
}
```

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型   | 是否必须 | 备注             |
| ------ | ------ | -------- | ---------------- |
| code   | number | 必须     | 1 成功，0 失败   |
| msg    | string | 非必须   | 提示信息         |
| data   | object | 非必须   | 返回的数据       |
| \|- id | string | 必须     | 新增观演人 id    |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": "301"
  }
}
```

### 1.4 备注说明

- 同一用户证件号重复 → 拒绝（业务前置查 + `uk_user_idcard` 唯一索引兜底）；
- 每用户上限 20 条（服务端校验，防刷表）；
- userId 从 ThreadLocal（登录态）取，前端传的一律不信。

## 2. 删除观演人

### 2.1 基本信息

> 请求路径：/user/attendee/{id}
>
> 请求方式：DELETE
>
> 接口描述：删除当前用户的一名观演人

### 2.2 请求参数

参数格式：路径参数

参数说明：

| 参数名 | 类型   | 是否必须 | 备注      |
| ------ | ------ | -------- | --------- |
| id     | string | 必须     | 观演人 id |

请求参数样例：

```
/user/attendee/301
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型   | 是否必须 | 备注           |
| ------ | ------ | -------- | -------------- |
| code   | number | 必须     | 1 成功，0 失败 |
| msg    | string | 非必须   | 提示信息       |
| data   | object | 非必须   | 无             |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": null
}
```

### 2.4 备注说明

- **归属校验（IDOR 防护样板）**：`DELETE ... WHERE id=? AND user_id=当前用户`，影响行数=0 报"观演人不存在"——不区分"不存在"与"不是你的"，防越权探测；
- 已被订单引用的观演人可以删（历史订单存的是快照，不受影响）。

## 3. 修改观演人

### 3.1 基本信息

> 请求路径：/user/attendee/{id}
>
> 请求方式：PUT
>
> 接口描述：修改当前用户的一名观演人信息（全量更新）

### 3.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注          |
| -------- | ------ | -------- | ------------- |
| name     | string | 必须     | 姓名          |
| idCardNo | string | 必须     | 18 位身份证号 |
| phone    | string | 非必须   | 联系电话      |

请求参数样例：

```json
{
  "name": "陈晓翔",
  "idCardNo": "440103200501011234",
  "phone": "13911112222"
}
```

### 3.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型   | 是否必须 | 备注           |
| ------ | ------ | -------- | -------------- |
| code   | number | 必须     | 1 成功，0 失败 |
| msg    | string | 非必须   | 提示信息       |
| data   | object | 非必须   | 无             |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": null
}
```

### 3.4 备注说明

- 归属校验同删除（`WHERE id=? AND user_id=?`）；
- 修改后的证件号需重新过唯一性检查（本用户内不得重复）。

## 4. 我的观演人列表

### 4.1 基本信息

> 请求路径：/user/attendee/list
>
> 请求方式：GET
>
> 接口描述：查询当前用户的全部观演人（下单选人时使用，不分页）

### 4.2 请求参数

无

### 4.3 响应数据

参数格式：application/json

参数说明：

| 参数名      | 类型      | 是否必须 | 备注                       |
| ----------- | --------- | -------- | -------------------------- |
| code        | number    | 必须     | 1 成功，0 失败             |
| msg         | string    | 非必须   | 提示信息                   |
| data        | object[]  | 非必须   | 观演人列表                 |
| \|- id      | string    | 必须     | 观演人 id                  |
| \|- name    | string    | 必须     | 姓名                       |
| \|- idCardNo | string   | 必须     | 证件号（脱敏展示）         |
| \|- phone   | string    | 非必须   | 联系电话（脱敏）           |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": [
    {
      "id": "301",
      "name": "陈晓翔",
      "idCardNo": "4401**********1234",
      "phone": "138****1234"
    },
    {
      "id": "302",
      "name": "李栗子",
      "idCardNo": "4401**********5678",
      "phone": null
    }
  ]
}
```

### 4.4 备注说明

- **证件号列表页脱敏**（`4401**********1234`），完整值只在下单确认环节内部使用；
- 按 id 倒序（新添加的在前）。
