# 云票接口文档 · 04 交易模块（P1 普通版）

> 前缀 `/user/orders`、`/user/pay`，需用户鉴权。
> **P1 范围**：下单为同步扣库存（条件更新 + 乐观锁，走公开池）；支付为 mock，P3 换支付宝沙箱（只换实现不换契约）；退票闭环 P4。

## 1. 创建订单（锁座）

### 1.1 基本信息

> 请求路径：/user/orders
>
> 请求方式：POST
>
> 接口描述：选定场次票档与观演人，创建待支付订单并锁定库存；15 分钟内未支付自动取消

### 1.2 请求参数

参数格式：application/json

参数说明：

| 参数名              | 类型      | 是否必须 | 备注                                   |
| ------------------- | --------- | -------- | -------------------------------------- |
| sessionId           | string    | 必须     | 场次 id                                |
| items               | object [] | 必须     | 1~5 个票档项                           |
| \|- categoryId      | string    | 必须     | 票档 id                                |
| \|- attendeeIds     | string [] | 必须     | 观演人 id 列表，**每人一票**，数量 = 列表长度 |

请求参数样例：

```json
{
  "sessionId": "601",
  "items": [
    {
      "categoryId": "701",
      "attendeeIds": ["301", "302"]
    },
    {
      "categoryId": "702",
      "attendeeIds": ["303"]
    }
  ]
}
```

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名         | 类型   | 是否必须 | 备注                          |
| -------------- | ------ | -------- | ----------------------------- |
| code           | number | 必须     | 1 成功，0 失败                |
| msg            | string | 非必须   | 提示信息（失败原因：库存不足/限购/证件已购等） |
| data           | object | 非必须   | 返回的数据                    |
| \|- orderId    | string | 必须     | 订单 id                       |
| \|- orderNo    | string | 必须     | 业务订单号                    |
| \|- payAmount  | number | 必须     | 应付金额（服务端重算）        |
| \|- expireTime | string | 必须     | 支付截止时间（now+15 分钟）   |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "orderId": "8001",
    "orderNo": "CT202610022200000001",
    "payAmount": 2940.00,
    "expireTime": "2026-10-02 22:45:00"
  }
}
```

### 1.4 备注说明（校验链，顺序即实现顺序）

1. 场次状态必须"销售中"；
2. 观演人归属校验（都是当前用户的）+ **本场证件未购**校验（P1 查 order_item 快照判重——`JOIN orders` 过滤状态，**覆盖待支付占用**，取消/退款自动释放；P3 换 Lua Set `idcard:{sessionId}`）；
3. 限购校验：同一票档累计 ≤ limit_per_user；
4. **金额服务端重算**：unit_price × 数量，pay_amount = amount（P1 无券），前端传的金额一律不信；
5. 扣库存：`UPDATE ticket_category SET stock=stock-n, sold_count=sold_count+n WHERE id=? AND stock>=n`，影响行数=0 → 库存不足（条件更新防超卖 + 乐观锁插件生效）；
6. 插订单 + **票位明细（一行一个观演人，写入姓名/证件快照）**，`order_no` 唯一索引兜底幂等；整体 `@Transactional`，失败已扣库存回补；
7. P3 此接口改造为秒杀链路：Sentinel 限流 → 防重 token → Lua 双池预扣 → RocketMQ 异步落单，接口路径与入参不变。

## 2. 模拟支付成功

### 2.1 基本信息

> 请求路径：/user/pay/mock/{orderNo}
>
> 请求方式：POST
>
> 接口描述：模拟第三方支付成功回调（P1 专用）；P3 整体替换为支付宝沙箱下单 + 异步回调验签，前端调用方式不变

### 2.2 请求参数

参数格式：路径参数

参数说明：

| 参数名   | 类型   | 是否必须 | 备注       |
| -------- | ------ | -------- | ---------- |
| orderNo  | string | 必须     | 业务订单号 |

请求参数样例：

```
/user/pay/mock/CT202610022200000001
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| 参数名        | 类型   | 是否必须 | 备注                              |
| ------------- | ------ | -------- | --------------------------------- |
| code          | number | 必须     | 1 成功，0 失败                    |
| msg           | string | 非必须   | 提示信息                          |
| data          | object | 非必须   | 返回的数据                        |
| \|- payStatus | string | 必须     | SUCCESS / 已支付 / 已取消（幂等） |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "payStatus": "SUCCESS"
  }
}
```

### 2.4 备注说明

- **回调幂等样板**：`UPDATE orders SET status=已支付 WHERE order_no=? AND status=待支付` 条件更新，影响行数=0 说明订单已支付/已取消，直接返回当前状态不重复处理；
- 写 payment 流水（out_trade_no 唯一索引兜底）；
- P1 同步出票（order_item 票位**一对一实体化**成 ticket 记录，实名快照随之复制）；P3 改 MQ 异步出票 + 本地消息表；
- **支付 vs 取消的竞态**：若订单已被超时任务取消，本接口发现状态非待支付 → 返回"订单已取消"并不收款（P3 三重保障完整版含反向退款）。

## 3. 我的订单分页

### 3.1 基本信息

> 请求路径：/user/orders/page
>
> 请求方式：GET
>
> 接口描述：当前用户的订单列表，可按状态筛选

### 3.2 请求参数

参数格式：queryString

参数说明：

| 参数名   | 类型   | 是否必须 | 备注                                   |
| -------- | ------ | -------- | -------------------------------------- |
| pageNum  | number | 非必须   | 默认 1                                 |
| pageSize | number | 非必须   | 默认 10                                |
| status   | number | 非必须   | 0待支付 1已支付 2已出票 3已核销 4已完成 5已取消 6退款中 7已退款 |

请求参数样例：

```shell
/user/orders/page?status=2&pageNum=1&pageSize=10
```

### 3.3 响应数据

参数格式：application/json

参数说明：

| 参数名          | 类型      | 是否必须 | 备注           |
| --------------- | --------- | -------- | -------------- |
| code            | number    | 必须     | 1 成功，0 失败 |
| msg             | string    | 非必须   | 提示信息       |
| data            | object    | 必须     | 分页数据       |
| \|- total       | number    | 必须     | 总记录数       |
| \|- rows        | object [] | 必须     | 数据列表       |
| \|- orderId     | string    | 非必须   | 订单 id        |
| \|- orderNo     | string    | 非必须   | 订单号         |
| \|- showTitle   | string    | 非必须   | 演出标题       |
| \|- sessionTime | string    | 非必须   | 场次时间       |
| \|- payAmount   | number    | 非必须   | 应付金额       |
| \|- status      | number    | 非必须   | 状态           |
| \|- statusDesc  | string    | 非必须   | 状态描述       |
| \|- expireTime  | string    | 非必须   | 支付截止（待支付单前端做倒计时） |
| \|- createTime  | string    | 非必须   | 下单时间       |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 5,
    "rows": [
      {
        "orderId": "8001",
        "orderNo": "CT202610022200000001",
        "showTitle": "星野巡回演唱会·广州站",
        "sessionTime": "2026-11-21 19:30:00",
        "payAmount": 2940.00,
        "status": 2,
        "statusDesc": "已出票",
        "expireTime": "2026-10-02 22:45:00",
        "createTime": "2026-10-02 22:30:00"
      }
    ]
  }
}
```

### 3.4 备注说明

- 强制 `WHERE user_id=当前用户`（只看自己的）；
- **深分页游标优化是 P1 MySQL 深挖点**：常规 LIMIT 翻到深处变慢，游标版（`WHERE id < 上一页最后id`）做对比实验记录数字。

## 5. 取消订单（未支付）

### 5.1 基本信息

> 请求路径：/user/orders/{id}/cancel
>
> 请求方式：POST
>
> 接口描述：用户主动取消待支付订单，释放锁定的库存

### 5.2 请求参数

参数格式：路径参数

参数说明：

| 参数名 | 类型   | 是否必须 | 备注   |
| ------ | ------ | -------- | ------ |
| id     | string | 必须     | 订单 id |

请求参数样例：

```
/user/orders/8001/cancel
```

### 5.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型   | 是否必须 | 备注                           |
| ------ | ------ | -------- | ------------------------------ |
| code   | number | 必须     | 1 成功，0 失败                 |
| msg    | string | 非必须   | 失败原因如"订单状态已变化"     |
| data   | object | 非必须   | 无                             |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": null
}
```

### 5.4 备注说明

- **条件更新抢占**：`UPDATE orders SET status=已取消 WHERE id=? AND user_id=? AND status=待支付`，影响行数=0 → "订单状态已变化"（可能已支付或已被超时取消）；
- 成功后按 `pool_type` 回补公开池库存（P1 单池来源，字段先行）；
- **与支付回调的并发竞态**：两边都走 CAS，只可能有一个赢——P3 三重保障的雏形。

## 6. 申请退票（占位 · P4 实现）

### 6.1 基本信息

> 请求路径：/user/refunds
>
> 请求方式：POST
>
> 接口描述：对"已出票"的票发起退票申请（P4 实现契约，先行冻结）

### 6.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注     |
| -------- | ------ | -------- | -------- |
| ticketId | string | 必须     | 票 id    |
| reason   | string | 非必须   | 退款原因 |

### 6.3 响应数据

参数格式：application/json

参数说明：通用 Result，data 为 `{ refundNo }`

### 6.4 备注说明

- P4 落位：退票规则策略（提前 48h 免费 / 48h 内收手续费 / 开演后不可退；会员免手续费）→ 生成退款单 → 主办方审核（会员优先队列）→ 支付宝原路退款 → 票状态置已退款 + 库存按池回补；
- 手续费金额由服务端策略计算，接口响应中返回 `refundAmount`。
