# 云票接口文档 · 01 认证模块

> 三区各自独立（`/user/auth` `/merchant/auth` `/admin/auth`），JWT 密钥互相隔离；注册/登录接口本身免鉴权。

## 1. 用户注册

### 1.1 基本信息

> 请求路径：/user/auth/register
>
> 请求方式：POST
>
> 接口描述：用户注册，注册成功自动登录并下发 JWT 令牌

### 1.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注                       |
| -------- | ------ | -------- | -------------------------- |
| phone    | string | 必须     | 大陆手机号                 |
| password | string | 必须     | 密码，6~20 位              |
| nickname | string | 非必须   | 昵称，不传默认"票友_手机尾号4位" |

请求参数样例：

```json
{
  "phone": "13800001234",
  "password": "abc123456"
}
```

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型   | 是否必须 | 备注                    |
| ---------- | ------ | -------- | ----------------------- |
| code       | number | 必须     | 1 成功，0 失败          |
| msg        | string | 非必须   | 提示信息                |
| data       | object | 非必须   | 返回的数据              |
| \|- token  | string | 必须     | JWT 令牌（用户端密钥，7 天） |
| \|- userId | string | 必须     | 用户 id                 |
| \|- nickname | string | 必须   | 昵称                    |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEwMDF9.xxxxx",
    "userId": "1001",
    "nickname": "票友_1234"
  }
}
```

### 1.4 备注说明

- 手机号由 `uk_phone` 唯一索引兜底：并发重复注册第二个插入失败，捕获冲突转提示"该手机号已注册"；
- 密码 BCrypt 加密存储，库中无明文；
- nickname 不传时服务端生成，不信任前端。

## 2. 用户登录

### 2.1 基本信息

> 请求路径：/user/auth/login
>
> 请求方式：POST
>
> 接口描述：用户手机号 + 密码登录，成功下发 JWT 令牌

### 2.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注          |
| -------- | ------ | -------- | ------------- |
| phone    | string | 必须     | 注册手机号    |
| password | string | 必须     | 注册时的密码  |

请求参数样例：

```json
{
  "phone": "13800001234",
  "password": "abc123456"
}
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型   | 是否必须 | 备注           |
| ---------- | ------ | -------- | -------------- |
| code       | number | 必须     | 1 成功，0 失败 |
| msg        | string | 非必须   | 提示信息       |
| data       | object | 非必须   | 返回的数据     |
| \|- token  | string | 必须     | JWT 令牌       |
| \|- userId | string | 必须     | 用户 id        |
| \|- nickname | string | 必须   | 昵称           |
| \|- vipLevel | number | 必须   | 0 普通 / 1 会员 |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEwMDF9.xxxxx",
    "userId": "1001",
    "nickname": "票友_1234",
    "vipLevel": 0
  }
}
```

### 2.4 备注说明

- 密码校验：BCrypt.matches(明文, 库中摘要)，不比较明文；
- 账号不存在与密码错误返回**同一提示**"账号或密码错误"（防账号探测）；
- status=0（禁用）拒绝登录，提示"账号已被禁用"；
- 登录成功后 token 放请求头 `Authorization`，后续所有 /user/** 接口必需；
- 登录失败次数限流（Redis 计数）为 P4 增强项。

## 3. 主办方登录

### 3.1 基本信息

> 请求路径：/merchant/auth/login
>
> 请求方式：POST
>
> 接口描述：主办方以联系人手机号 + 密码登录管理端

### 3.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注                    |
| -------- | ------ | -------- | ----------------------- |
| phone    | string | 必须     | 入驻时登记的联系电话    |
| password | string | 必须     | 入驻开通时设置的密码    |

请求参数样例：

```json
{
  "phone": "13900005678",
  "password": "mch123456"
}
```

### 3.3 响应数据

参数格式：application/json

参数说明：

| 参数名       | 类型   | 是否必须 | 备注                          |
| ------------ | ------ | -------- | ----------------------------- |
| code         | number | 必须     | 1 成功，0 失败                |
| msg          | string | 非必须   | 提示信息                      |
| data         | object | 非必须   | 返回的数据                    |
| \|- token    | string | 必须     | JWT 令牌（主办方端密钥）      |
| \|- merchantId | string | 必须   | 主办方 id                     |
| \|- name     | string | 必须     | 主办方名称                    |
| \|- status   | number | 必须     | 0 待审核 1 正常 2 禁用        |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJtZXJjaGFudElkIjoyMH0.yyyyy",
    "merchantId": "20",
    "name": "星野演出有限公司",
    "status": 1
  }
}
```

### 3.4 备注说明

- status=0（待审核）与 status=2（禁用）都拒绝，但提示不同："入驻审核中，请等待平台确认" / "账号已被禁用"；
- 主办方账号由平台入驻审核开通，无自助注册；
- JWT 使用主办方端独立密钥，用户端 token 调 /merchant/** 必须无效（双端隔离）。

## 4. 平台管理员登录

### 4.1 基本信息

> 请求路径：/admin/auth/login
>
> 请求方式：POST
>
> 接口描述：平台管理员登录审核后台

### 4.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型   | 是否必须 | 备注   |
| -------- | ------ | -------- | ------ |
| username | string | 必须     | 登录名 |
| password | string | 必须     | 密码   |

请求参数样例：

```json
{
  "username": "admin",
  "password": "admin@2026"
}
```

### 4.3 响应数据

参数格式：application/json

参数说明：

| 参数名      | 类型   | 是否必须 | 备注       |
| ----------- | ------ | -------- | ---------- |
| code        | number | 必须     | 1 成功，0 失败 |
| msg         | string | 非必须   | 提示信息   |
| data        | object | 非必须   | 返回的数据 |
| \|- token   | string | 必须     | JWT 令牌（平台端密钥） |
| \|- adminId | string | 必须     | 管理员 id  |
| \|- realName | string | 非必须 | 姓名       |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJhZG1pbklkIjoxfQ.zzzzz",
    "adminId": "1",
    "realName": "平台超管"
  }
}
```

### 4.4 备注说明

- 管理员账号由 SQL 初始化脚本插入，无注册接口；
- 密码错误提示与用户端一致（防探测）。

## 5. 查询当前登录信息

### 5.1 基本信息

> 请求路径：/user/auth/me（主办方端 /merchant/auth/me、平台端 /admin/auth/me 结构同构）
>
> 请求方式：GET
>
> 接口描述：前端刷新页面后恢复登录态

### 5.2 请求参数

无（身份从 Authorization 的 JWT 中解析）

### 5.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型   | 是否必须 | 备注           |
| ---------- | ------ | -------- | -------------- |
| code       | number | 必须     | 1 成功，0 失败 |
| msg        | string | 非必须   | 提示信息       |
| data       | object | 非必须   | 当前登录用户信息 |
| \|- userId | string | 必须     | 用户 id        |
| \|- phone  | string | 必须     | 手机号（脱敏） |
| \|- nickname | string | 必须   | 昵称           |
| \|- vipLevel | number | 必须   | 0 普通 / 1 会员 |
| \|- points | number | 必须     | 积分余额       |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "userId": "1001",
    "phone": "138****1234",
    "nickname": "票友_1234",
    "vipLevel": 0,
    "points": 120
  }
}
```

### 5.4 备注说明

- 手机号脱敏返回（138\*\*\*\*1234）；
- 401 情况：token 缺失/过期/伪造——拦截器直接返回，不走全局异常处理器。

---

## 6. 退出登录

### 6.1 基本信息

> 请求路径：无（v1 无接口）
>
> 请求方式：-
>
> 接口描述：v1 前端删除本地 token 即可（JWT 无状态）；v2 演进为 Redis 黑名单 / 同端登录冲突检测（Sa-Token），届时补充本接口。
