# 08 · 会员模块

> **P1 定位：会员"空壳"** —— 只做开通与查询，**不含任何购票权益**（双池/会员价/退票权益统一 P3 落地，见 `docs/会员系统设计.md`）。
> 虚拟订单复用 04 的订单/支付链路：`order_type=2(VIP)`，无演出/场次/主办方。
> **本模块 3 个接口**：用户端 2（查状态 / 开通）+ 平台端 1（VIP 订单分页）。

---

## 1. 查询会员状态

### 1.1 基本信息

> 请求路径：/user/vip
>
> 请求方式：GET
>
> 接口描述：查询当前登录用户的会员状态与可开通档位（前端"我的会员"页展示）

### 1.2 请求参数

无

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
| ------ | ------------------- | -------- | ---- |
| code | Integer（number） | 必须 | 1 成功，0 失败 |
| msg | String（string） | 非必须 | 提示信息 |
| data | UserVipVO（object） | 必须 | 会员信息 |
| \|- vipLevel | Integer（number） | 必须 | 0 普通 / 1 会员 |
| \|- vipExpireTime | LocalDateTime（string） | 非必须 | 会员到期时间（非会员为 null）|
| \|- isVip | Boolean（boolean） | 必须 | 是否有效会员（vipLevel=1 且未过期）|
| \|- plans | List<VipPlanVO>（object[]） | 必须 | 可开通档位 |
| \|- \|- planCode | String（string） | 必须 | 档位编码：`MONTH` / `YEAR` |
| \|- \|- planName | String（string） | 必须 | 档位名：月卡 / 年卡 |
| \|- \|- months | Integer（number） | 必须 | 时长（月）|
| \|- \|- price | BigDecimal（number） | 必须 | 价格（元）|

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "vipLevel": 1,
    "vipExpireTime": "2026-12-20 20:00:00",
    "isVip": true,
    "plans": [
      { "planCode": "MONTH", "planName": "月卡", "months": 1, "price": 19.90 },
      { "planCode": "YEAR",  "planName": "年卡", "months": 12, "price": 199.00 }
    ]
  }
}
```

### 1.4 备注说明

- **过期判断惰性**：`vipLevel=1` 但 `vipExpireTime < now` → 返回 `isVip=false`（不依赖定时任务改字段）；
- **`isVip` 是后端计算值**（`vipLevel=1 && vipExpireTime > now`），**不落库**；数据库只存 `vip_level` 与 `vip_expire_time`，**没有"是否过期"标志字段**；
- **三态派生**：非会员（`vipLevel=0`）/ 有效会员（`isVip=true`）/ **过期会员**（`vipLevel=1 && isVip=false`）—— 前端用 `vipLevel + vipExpireTime` 自行派生，用于"过期挽留"等场景，无需额外字段；
- 档位为后端常量（P1 不建套餐表）：`MONTH`（1 个月，19.90 元）/ `YEAR`（12 个月，199.00 元）；
- 强制按当前登录用户查询（`WHERE id = 当前用户`），无越权可能。

## 2. 开通会员（创建虚拟订单）

### 2.1 基本信息

> 请求路径：/user/vip/orders
>
> 请求方式：POST
>
> 接口描述：创建会员开通订单（虚拟商品，复用订单/支付链路；支付成功后会员立即生效）

### 2.2 请求参数

参数格式：application/json

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
| ------ | ------------------- | -------- | ---- |
| planCode | String（string） | 必须 | 档位编码：`MONTH` / `YEAR` |

请求参数样例：

```json
{
  "planCode": "MONTH"
}
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
| ------ | ------------------- | -------- | ---- |
| code | Integer（number） | 必须 | 1 成功，0 失败 |
| msg | String（string） | 非必须 | 提示信息 |
| data | UserCreateOrderVO（object） | 必须 | 订单信息（复用 04 §1 创建订单出参结构）|
| \|- orderId | Long（string） | 必须 | 订单 id |
| \|- orderNo | String（string） | 必须 | 订单号 |
| \|- payAmount | BigDecimal（number） | 必须 | 应付金额（= 档位价）|
| \|- expireTime | LocalDateTime（string） | 必须 | 支付截止时间（15 分钟）|

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "orderId": "23",
    "orderNo": "20261120203000123456",
    "payAmount": 19.90,
    "expireTime": "2026-11-20 20:45:00"
  }
}
```

### 2.4 备注说明

- **落库**：`order_type = 2(VIP)`；`show_id / session_id / merchant_id = NULL`；`pool_type = 1`（占位，无库存含义）；`vip_plan_code = planCode`（档位快照，供平台订单列表翻译）；
- **本接口只创建订单，不调用任何支付接口**：返回 orderNo/payAmount/expireTime 给前端，由前端另行发起支付；
- **后续支付（前端拿到 orderNo 后调用）**：`POST /user/pay/mock/{orderNo}`（04 §2，P1 模拟）—— 支付成功后：订单直接置 **已完成(4)**（无出票/核销）、`user.vip_level = 1`、`vip_expire_time` 叠加；
- **续费叠加**：原到期在 future → 从原到期 +N 月；已过期 → 从 now +N 月；
- **过期**：未支付 15 分钟作废（与普通订单同 `expire_time` 机制）；
- **归属**：VIP 订单归属平台（无主办方），主办方订单查询天然不可见；
- **平台端查看**：`GET /admin/vip/orders/page`（见本文 §3）。

## 3. 平台端：VIP 订单分页

### 3.1 基本信息

> 请求路径：/admin/vip/orders/page
>
> 请求方式：GET
>
> 接口描述：平台查看会员开通订单（财务/运营视角；VIP 订单无主办方，归属平台）

### 3.2 请求参数

参数格式：queryString

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
| ------ | ------------------- | -------- | ---- |
| pageNum | Integer（number） | 非必须 | 默认 1 |
| pageSize | Integer（number） | 非必须 | 默认 10 |
| status | Integer（number） | 非必须 | 订单状态（0 待支付 / 4 已完成 / 5 已取消，不传查全部）|
| phone | String（string） | 非必须 | 用户手机号精确匹配 |
| planCode | String（string） | 非必须 | 档位：`MONTH` / `YEAR` |

请求参数样例：

```shell
/admin/vip/orders/page?status=4&pageNum=1&pageSize=10
```

### 3.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
| ------ | ------------------- | -------- | ---- |
| code | Integer（number） | 必须 | 1 成功，0 失败 |
| msg | String（string） | 非必须 | 提示信息 |
| data | PageResult<AdminVipOrderVO>（object） | 必须 | 分页数据 |
| \|- total | Integer（number） | 必须 | 总记录数 |
| \|- rows | List<AdminVipOrderVO>（object[]） | 必须 | 数据列表 |
| \|- orderId | Long（string） | 必须 | 订单 id |
| \|- orderNo | String（string） | 必须 | 订单号 |
| \|- userId | Long（string） | 必须 | 用户 id |
| \|- phone | String（string） | 非必须 | 用户手机号（脱敏）|
| \|- nickname | String（string） | 非必须 | 用户昵称 |
| \|- planName | String（string） | 必须 | 档位名（月卡/年卡）|
| \|- months | Integer（number） | 必须 | 时长（月）|
| \|- amount | BigDecimal（number） | 必须 | 订单金额 |
| \|- status / statusDesc | Integer / String（number/string） | 必须 | 0 待支付 / 4 已完成 / 5 已取消 |
| \|- createTime | LocalDateTime（string） | 必须 | 下单时间 |
| \|- payTime | LocalDateTime（string） | 非必须 | 支付时间（未支付为 null）|

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 12,
    "rows": [
      {
        "orderId": "23",
        "orderNo": "20261120203000123456",
        "userId": "1001",
        "phone": "138****1234",
        "nickname": "票友_1234",
        "planName": "月卡",
        "months": 1,
        "amount": 19.90,
        "status": 4,
        "statusDesc": "已完成",
        "createTime": "2026-11-20 20:30:00",
        "payTime": "2026-11-20 20:31:12"
      }
    ]
  }
}
```

### 3.4 备注说明

- 只查 `order_type = 2(VIP)` 的订单（普通票务订单走主办方端 06 §7，平台不看交易明细）；
- `planName/months` 由后端按 `orders.vip_plan_code` 快照翻译（MONTH→月卡/1 月、YEAR→年卡/12 月）；
- 数据权限：平台全局可见（无 merchant 过滤）；
- 写操作（改状态等）不在此接口，仅查询。
