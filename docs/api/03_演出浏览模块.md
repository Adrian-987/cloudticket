# 云票接口文档 · 03 演出浏览模块（用户端）

> 前缀 `/user/shows`、`/user/sessions`。列表/分类/详情均免鉴权（浏览不强制登录，下单才需要）。
>
> **拆分设计说明**：演出详情拆为两个接口——`3 演出详情`（静态内容：演出+场馆+场次骨架）与 `4 场次票档余量`（动态数据：票档与剩余库存）。原因：① 静态内容与动态余量的缓存策略不同（P2 详情长缓存，余量走 Redis 近实时）；② 对应真实产品交互（详情页 → 点击"选票" → 二级面板拉票档余量）；③ 抢票期余量接口可独立限流（P3 Sentinel 落点）。用户点开选票面板时多一次请求，收益大于代价。

## 1. 演出分类列表

### 1.1 基本信息

> 请求路径：/user/shows/category-list
>
> 请求方式：GET
>
> 接口描述：返回演出分类常量，供列表页筛选下拉框使用

### 1.2 请求参数

无

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型     | 是否必须 | 备注           |
| ------ | -------- | -------- | -------------- |
| code   | number   | 必须     | 1 成功，0 失败 |
| msg    | string   | 非必须   | 提示信息       |
| data   | string[] | 非必须   | 分类名称列表   |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": ["演唱会", "话剧", "音乐会", "脱口秀", "音乐节", "其他"]
}
```

### 1.4 备注说明

- P1 分类是常量枚举（不做分类表），以后要运营自定义分类再加表，接口路径不变。

## 2. 演出分页列表

### 2.1 基本信息

> 请求路径：/user/shows/page
>
> 请求方式：GET
>
> 接口描述：按条件分页查询"销售中"的演出（用户端首页/列表页）

### 2.2 请求参数

参数格式：queryString

参数说明：

| 参数名    | 类型    | 是否必须 | 备注                                    |
| --------- | ------- | -------- | --------------------------------------- |
| pageNum   | number  | 非必须   | 页码，默认 1                            |
| pageSize  | number  | 非必须   | 每页条数，默认 10，上限 100             |
| category  | string  | 非必须   | 分类精确匹配                            |
| city      | string  | 非必须   | 场馆城市（联 venue 过滤）               |
| keyword   | string  | 非必须   | 标题模糊匹配（P1 LIKE，P6 演进为 ES）   |

请求参数样例：

```shell
/user/shows/page?category=演唱会&city=广州&keyword=星野&pageNum=1&pageSize=10
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| 参数名         | 类型      | 是否必须 | 备注                       |
| -------------- | --------- | -------- | -------------------------- |
| code           | number    | 必须     | 1 成功，0 失败             |
| msg            | string    | 非必须   | 提示信息                   |
| data           | object    | 必须     | 分页数据                   |
| \|- total      | number    | 必须     | 总记录数                   |
| \|- rows       | object [] | 必须     | 数据列表                   |
| \|- id         | string    | 非必须   | 演出 id                    |
| \|- title      | string    | 非必须   | 标题                       |
| \|- category   | string    | 非必须   | 分类                       |
| \|- coverUrl   | string    | 非必须   | 封面图地址                 |
| \|- venueName  | string    | 非必须   | 场馆名称                   |
| \|- city       | string    | 非必须   | 城市                       |
| \|- minPrice   | number    | 非必须   | 最低票档价（"xx 元起"）    |
| \|- status     | number    | 非必须   | 固定为 4（销售中）         |
| \|- statusDesc | string    | 非必须   | "销售中"                   |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 23,
    "rows": [
      {
        "id": "501",
        "title": "星野巡回演唱会·广州站",
        "category": "演唱会",
        "coverUrl": "https://oss.cloudticket.cn/cover/501.jpg",
        "venueName": "星海体育馆",
        "city": "广州",
        "minPrice": 380.00,
        "status": 4,
        "statusDesc": "销售中"
      }
    ]
  }
}
```

### 2.4 备注说明

- 固定只查 `status=销售中`；
- 排序：`sold_count DESC`（热卖优先）；
- **落位**：P2 该接口接缓存三件套 + 多级缓存，是第一组压测对象（直查 DB vs 单级缓存 vs 多级缓存三场景对比）；
- keyword 的 LIKE 查询在 P6 演进为 ES（接口路径与响应结构不变，只换实现）。

## 3. 演出详情（静态内容）

### 3.1 基本信息

> 请求路径：/user/shows/{id}
>
> 请求方式：GET
>
> 接口描述：查询演出静态信息（演出 + 场馆 + 场次骨架），**不含票档与库存余量**；详情页首屏调用

### 3.2 请求参数

参数格式：路径参数

参数说明：

| 参数名 | 类型   | 是否必须 | 备注   |
| ------ | ------ | -------- | ------ |
| id     | string | 必须     | 演出 id |

请求参数样例：

```
/user/shows/501
```

### 3.3 响应数据

参数格式：application/json

参数说明：

| 参数名             | 类型      | 是否必须 | 备注                          |
| ------------------ | --------- | -------- | ----------------------------- |
| code               | number    | 必须     | 1 成功，0 失败                |
| msg                | string    | 非必须   | 提示信息                      |
| data               | object    | 必须     | 演出详情                      |
| \|- id             | string    | 必须     | 演出 id                       |
| \|- title          | string    | 必须     | 标题                          |
| \|- category       | string    | 必须     | 分类                          |
| \|- coverUrl       | string    | 非必须   | 封面                          |
| \|- detail         | string    | 非必须   | 图文详情（富文本）            |
| \|- guide          | string    | 非必须   | 观演指南（证件/时间/交通）    |
| \|- minPrice       | number    | 必须     | 最低票档价（详情页显示价格区间用） |
| \|- maxPrice       | number    | 必须     | 最高票档价                    |
| \|- status         | number    | 必须     | 状态                          |
| \|- statusDesc     | string    | 必须     | 状态描述                      |
| \|- venue          | object    | 必须     | 场馆信息                      |
| \|- \|- name       | string    | 必须     | 场馆名称                      |
| \|- \|- city       | string    | 必须     | 城市                          |
| \|- \|- address    | string    | 必须     | 详细地址                      |
| \|- sessions       | object [] | 必须     | 场次列表（仅骨架，无票档）    |
| \|- \|- id         | string    | 必须     | 场次 id（调接口 4 用）        |
| \|- \|- sessionName | string   | 非必须   | 场次名                        |
| \|- \|- sessionTime | string   | 必须     | 演出开始时间                  |
| \|- \|- saleStartTime | string | 必须     | 开售时间（前端展示"xx日 10:00 开抢"） |
| \|- \|- saleEndTime   | string | 必须     | 停售时间                      |
| \|- \|- status / statusDesc |  | 必须     | 未开售/销售中/已结束          |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": "501",
    "title": "星野巡回演唱会·广州站",

    "guide": "凭身份证原件入场；开场前 90 分钟开始检票；地铁 3 号线星海站 B 口",
    "minPrice": 380.00,
    "maxPrice": 1280.00,
    "status": 4,
    "statusDesc": "销售中",
    "venue": {
      "name": "星海体育馆",
      "city": "广州",
      "address": "天河区体育西路 199 号"
    },
    "sessions": [
      {
        "id": "601",
        "sessionName": "周六晚场",
        "sessionTime": "2026-11-21 19:30:00",
        "saleStartTime": "2026-10-10 10:00:00",
        "saleEndTime": "2026-11-21 19:00:00",
        "status": 1,
        "statusDesc": "销售中"
      }
    ]
  }
}
```

### 3.4 备注说明

- id 不存在 → code=0 "演出不存在"（P2 接入布隆过滤器前置拦截，防缓存穿透）；
- **本接口整体是"准静态"内容**——只有审核/上下架/编辑时才变，是 P2 缓存体系的理想对象（逻辑过期 + 互斥重建 + TTL 抖动 + 开售前预热）；
- minPrice/maxPrice 从票档聚合计算，随详情一起缓存；
- 场次骨架带 status：前端渲染"未开售/销售中/已结束"标签并控制"选票"按钮是否可点。

## 4. 场次票档余量查询（动态数据）

### 4.1 基本信息

> 请求路径：/user/sessions/{sessionId}/categories
>
> 请求方式：GET
>
> 接口描述：用户在详情页点击"选票"后，查询该场次的票档与实时余量（选票面板数据源）

### 4.2 请求参数

参数格式：路径参数

参数说明：

| 参数名    | 类型   | 是否必须 | 备注   |
| --------- | ------ | -------- | ------ |
| sessionId | string | 必须     | 场次 id |

请求参数样例：

```
/user/sessions/601/categories
```

### 4.3 响应数据

参数格式：application/json

参数说明：

| 参数名          | 类型      | 是否必须 | 备注                             |
| --------------- | --------- | -------- | -------------------------------- |
| code            | number    | 必须     | 1 成功，0 失败                   |
| msg             | string    | 非必须   | 提示信息                         |
| data            | object    | 必须     | 选票面板数据                     |
| \|- sessionId   | string    | 必须     | 场次 id                          |
| \|- status / statusDesc |   | 必须     | 场次实时状态（未开售面板置灰）   |
| \|- categories  | object [] | 必须     | 票档列表                         |
| \|- \|- id      | string    | 必须     | 票档 id（创建订单入参）          |
| \|- \|- name    | string    | 必须     | 票档名                           |
| \|- \|- price   | number    | 必须     | 票价                             |
| \|- \|- remainStock | number | 必须    | 公开池剩余 = stock - sold_count  |
| \|- \|- memberRemainStock | number | 必须 | 会员池剩余（非会员固定 0）   |
| \|- \|- limitPerUser | number | 必须    | 限购数量                         |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "sessionId": "601",
    "status": 1,
    "statusDesc": "销售中",
    "categories": [
      {
        "id": "701",
        "name": "内场VIP",
        "price": 1280.00,
        "remainStock": 320,
        "memberRemainStock": 0,
        "limitPerUser": 2
      },
      {
        "id": "702",
        "name": "看台A",
        "price": 380.00,
        "remainStock": 415,
        "memberRemainStock": 80,
        "limitPerUser": 4
      }
    ]
  }
}
```

### 4.4 备注说明

- **memberRemainStock 返回规则**：请求头带合法用户 token 且该用户是会员才返回真实值，否则固定 0（会员专属池在接口层的表达）；
- **落位（这个接口的使命随期数升级）**：P1 直查数据库；P2 余量部分改读 Redis；P3 抢票期它承受最高 QPS，Sentinel 对其单独限流，且余量以 Redis 为准（页面展示允许秒级误差，下单以 Lua 扣减结果为准）；
- 场次状态非"销售中"时正常返回结构（前端据 status 置灰面板），余量字段返回 0；
- 面试可讲：**详情（静态）与余量（动态）分离是缓存策略的前提**——混在一个接口里，要么余量脏读、要么静态内容白查库。
