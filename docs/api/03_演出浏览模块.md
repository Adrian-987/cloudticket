# 云票接口文档 · 03 演出浏览模块（用户端）

> 前缀 `/user/shows`、`/user/sessions`。列表/分类/详情均免鉴权（浏览不强制登录，下单才需要）。
>
> **拆分设计说明**：演出详情拆为两个接口——`3 演出详情`（静态内容：演出+场馆+场次骨架）与 `4 场次票档余量`（动态数据：票档与剩余库存）。原因：① 静态内容与动态余量的缓存策略不同（P2 详情长缓存，余量走 Redis 近实时）；② 对应真实产品交互（详情页 → 点击"选票" → 二级面板拉票档余量）；③ 抢票期余量接口可独立限流（P3 Sentinel 落点）。用户点开选票面板时多一次请求，收益大于代价。

> 请求方式：GET

| \|- label | String（string） | 必须    | 分类文案       |

响应数据样例：

- 分类在**全项目统一用 code 存储/传输**（`show_info.category` 为 TINYINT），展示文案由前端用本接口返回的 label 或后端返回的 `categoryDesc` 翻译（与 `status/statusDesc` 同一风格）。

### 2.2 请求参数

参数说明：

| 参数名    | 类型（Java / JSON）    | 是否必须 | 备注                                    |
| --------- | ------- | -------- | --------------------------------------- |
| pageNum   | Integer（number） | 非必须   | 页码，默认 1                            |
| pageSize  | Integer（number） | 非必须   | 每页条数，默认 10，上限 100             |
| category  | Integer（number） | 非必须   | 分类 code（1演唱会 2话剧 3音乐会 4脱口秀 5音乐节 6其他） |
| city      | String（string） | 非必须   | 场馆城市（联 venue 过滤）               |
| keyword   | String（string） | 非必须   | 标题模糊匹配（P1 LIKE，P6 演进为 ES）   |

请求参数样例：

```shell
/user/shows/page?category=1&city=广州&keyword=星野&pageNum=1&pageSize=10
```

### 2.3 响应数据

参数格式：application/json

参数说明：

| -------------- | --------- | -------- | -------------------------- |

| msg            | String（string） | 非必须   | 提示信息                   |
| data           | PageResult<UserShowVO>（object） | 必须     | 分页数据                   |
| \|- total      | Integer（number） | 必须     | 总记录数                   |
| \|- rows       | List<UserShowVO>（object[]） | 必须     | 数据列表                   |
| \|- id         | Long（string） | 非必须   | 演出 id                    |
| \|- title      | String（string） | 非必须   | 标题                       |
| \|- category   | Integer（number） | 非必须   | 分类 code（1~6）           |
| \|- categoryDesc | String（string） | 非必须   | 分类文案（"演唱会"）       |
| \|- coverUrl   | String（string） | 非必须   | 封面图地址                 |
| \|- venueName  | String（string） | 非必须   | 场馆名称                   |
| \|- city       | String（string） | 非必须   | 城市                       |
| \|- minPrice   | BigDecimal（number） | 非必须   | 最低票档价（"xx 元起"）    |
| \|- status     | Integer（number） | 非必须   | 固定为 4（销售中）         |
| \|- statusDesc | String（string） | 非必须   | "销售中"                   |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 23,
    "rows": [
      {
        "id": "501",
        "title": "星野巡回演唱会·广州站",
        "category": 1,
        "categoryDesc": "演唱会",
        "coverUrl": "https://oss.cloudticket.cn/cover/501.jpg",
        "venueName": "星海体育馆",
        "city": "广州",
        "minPrice": 380.00,
        "status": 4,
        "statusDesc": "销售中"
      }
    ]
  }
}
```

### 2.4 备注说明

- 固定只查 `status=销售中`；
- 排序：`sold_count DESC, id DESC`（热卖优先；id 兜底保证并列时排序稳定）；
- **缓存策略（P2，按"可复用性"分层）**：
  - **无 keyword 且 pageNum ≤ 50** → 走 Redis 结果缓存：key = `城市:分类:页码:每页条数`，TTL **30s + 随机抖动 0~30s**（防雪崩）；
  - **带 keyword 或深页（pageNum > 50）→ 不缓存，直查 DB**：关键词是无限组合/长尾，缓存会生产大量废 key；P6 关键词搜索演进为 ES（由 ES 承接检索与缓存）；
  - 缓存读写异常一律**降级直查 DB**（缓存故障不拖垮业务）；
- **落位**：P2 该接口是第一组压测对象（直查 vs 单级缓存）；列表只做**单级 Redis**（TTL 短 + 组合多，本地层收益小），多级缓存的对比在详情接口；
- keyword 的 LIKE 查询在 P6 演进为 ES（接口路径与响应结构不变，只换实现）。

## 4. 场次票档余量查询（动态数据）

### 4.1 基本信息

> 请求路径：/user/sessions/{sessionId}/categories
>
> 请求方式：GET
>
> 接口描述：用户在详情页点击"选票"后，查询该场次的票档与实时余量（选票面板数据源）

### 4.2 请求参数

参数格式：路径参数

参数说明：

| 参数名    | 类型（Java / JSON）   | 是否必须 | 备注   |
| --------- | ------ | -------- | ------ |
| sessionId | Long（string） | 必须     | 场次 id |

请求参数样例：

```
/user/sessions/601/categories
```

### 4.3 响应数据

参数格式：application/json

参数说明：

| 参数名          | 类型（Java / JSON）      | 是否必须 | 备注                             |
| --------------- | --------- | -------- | -------------------------------- |
| code            | Integer（number） | 必须     | 1 成功，0 失败                   |
| msg             | String（string） | 非必须   | 提示信息                         |
| data            | SessionStockVO（object） | 必须     | 选票面板数据                     |
| \|- sessionId   | Long（string） | 必须     | 场次 id                          |
| \|- status / statusDesc | Integer / String（number/string） | 必须     | 场次实时状态（未开售面板置灰）   |
| \|- categories  | List<CategoryRemainVO>（object[]） | 必须     | 票档列表                         |
| \|- \|- id      | Long（string） | 必须     | 票档 id（创建订单入参）          |
| \|- \|- name    | String（string） | 必须     | 票档名                           |
| \|- \|- price   | BigDecimal（number） | 必须     | 票价                             |
| \|- \|- remainStock | Integer（number） | 必须    | 公开池剩余 = stock - sold_count  |
| \|- \|- memberRemainStock | Integer（number） | 必须 | 会员池剩余（真实值；是否展示由前端按会员态决定） |
| \|- \|- limitPerUser | Integer（number） | 必须    | 限购数量                         |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "sessionId": "601",
    "status": 1,
    "statusDesc": "销售中",
    "categories": [
      {
        "id": "701",
        "name": "内场VIP",
        "price": 1280.00,
        "remainStock": 320,
        "memberRemainStock": 60,
        "limitPerUser": 2
      },
      {
        "id": "702",
        "name": "看台A",
        "price": 380.00,
        "remainStock": 415,
        "memberRemainStock": 80,
        "limitPerUser": 4
      }
    ]
  }
}
```

### 4.4 备注说明

- **memberRemainStock 返回真实值**（不按身份过滤）：会员池剩余照常返回；是否展示、怎么呈现（会员标签/置灰/登录引导）由**前端按登录态与页面设计决定**——后端不做"隐藏字段"的逻辑；
- **会员身份查询**：P1 会员为空壳（买票无特权），会员池**不参与售卖**；当前用户是否会员用 `GET /user/vip`（08 会员模块 §1）查询，前端据此决定会员池区域如何呈现；P3 起会员按身份优先购会员池；
- **落位（这个接口的使命随期数升级）**：P1 直查数据库；P2 余量部分改读 Redis；P3 抢票期它承受最高 QPS，Sentinel 对其单独限流，且余量以 Redis 为准（页面展示允许秒级误差，下单以 Lua 扣减结果为准）；
- 场次状态非"销售中"时正常返回结构（前端据 status 置灰面板），余量字段返回 0；
- **票档定义与库存拆分（v1.5）**：票档（座位等级）在同一演出的所有场次通用、票价统一（演出级 `ticket_category`）；余量是"场次 × 票档"的独立库存单元（`session_category_stock`）。本接口返回的是**按场次组装后的视图**，前端无需感知存储差异；
- 面试可讲：**详情（静态）与余量（动态）分离是缓存策略的前提**——混在一个接口里，要么余量脏读、要么静态内容白查库。

## 5. 热门演出 Top10（P2 新增）

### 5.1 基本信息

> 请求路径：/user/shows/hot
>
> 请求方式：GET
>
> 接口描述：首页「热门演出」榜单 —— 按当天浏览热度取前 10，不分页、不筛选

### 5.2 请求参数

参数格式：无

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
|--------|---------------------|----------|------|
| —— | —— | —— | 无参数 |

请求参数样例：

```shell
/user/shows/hot
```

### 5.3 响应数据

参数格式：application/json

参数说明：

| 参数名 | 类型（Java / JSON） | 是否必须 | 备注 |
|--------|---------------------|----------|------|
| code | Integer（number）| 必须 | 1 成功，0 失败 |
| msg | String（string）| 非必须 | 提示信息 |
| data | List<UserShowVO>（object[]）| 必须 | 榜单列表（最多 10 条，按热度降序）|
| \|- id | Long（string）| 必须 | 演出 id |
| \|- title | String（string）| 必须 | 演出标题 |
| \|- category | Integer（number）| 必须 | 分类 code |
| \|- categoryDesc | String（string）| 必须 | 分类描述 |
| \|- coverUrl | String（string）| 非必须 | 封面图 |
| \|- venueName | String（string）| 非必须 | 场馆名 |
| \|- city | String（string）| 非必须 | 城市 |
| \|- minPrice | BigDecimal（number）| 非必须 | 最低票价 |
| \|- status | Integer（number）| 必须 | 状态 code（3 审核通过 / 4 销售中）|
| \|- statusDesc | String（string）| 必须 | 状态描述（即将开售 / 销售中）|

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": [
    {
      "id": "1001",
      "title": "星野巡回演唱会·广州站",
      "category": 1,
      "categoryDesc": "演唱会",
      "coverUrl": "https://example.com/cover.jpg",
      "venueName": "广州大剧院",
      "city": "广州",
      "minPrice": 280.00,
      "status": 4,
      "statusDesc": "销售中"
    }
  ]
}
```

### 5.4 备注说明

- **数据源**：Redis ZSet `cloudticket:hot:shows:{yyyyMMdd}`，member = 演出 id，score = 当日热度分（**浏览 ×1**：详情接口被访问时 `ZINCRBY` +1，**异步执行**，不影响详情响应）；
- **取数**：`ZREVRANGE key 0 9` 取 Top10 → 按 id 批量查（优先走缓存/批量 SQL），组装为 `UserShowVO`；
- **每日切换**：key 带日期后缀，零点后自然累积新榜；旧榜保留 **7 天**（`EXPIRE`），期间可扩展"昨日榜单"；
- **空榜兜底**：当天无人浏览 → 返回空数组 `[]`，前端回退到"按销量排序的演出列表"（03 §2）；
- **榜单口径**：只保留**审核通过(3) / 销售中(4)** 的演出；已下架(6)/结束(5) 的取数后剔除；
- **落位**：P2 用 ZSet（秒级更新）；P6 若引入 ES，可切到 ES 热度聚合（接口路径与响应结构不变）；
- **与 03 §2 的关系**：§2 = 可筛选/可翻页的全量列表（热卖排序，offset 分页）；§5 = 固定 Top10 榜单（ZSet）——**热榜管"排"，分页管"翻"**。
