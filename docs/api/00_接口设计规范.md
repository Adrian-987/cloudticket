## 1. 风格

轻量 RESTful：资源名词复数 + HTTP 动词表语义，**状态流转类操作用动作式 POST**（如 `POST /user/orders/{id}/cancel`），不追求纯 REST 教条。

## 2. URL 分区（对应三个拦截器，物理隔离）

| 分区 | 前缀 | 身份 | JWT 密钥 |
|---|---|---|---|
| 用户端 | `/user/**` | 普通用户 | 密钥 A |
| 主办方端 | `/merchant/**` | 主办方 | 密钥 B |
| 平台端 | `/admin/**` | 平台管理员 | 密钥 C |

三区密钥互相独立——用户 token 拿去调管理端接口必须无效（双端隔离，苍穹同款）。

## 3. 鉴权

- 请求头：`Authorization: <JWT>`（不加 Bearer 前缀，v1 从简）
- 有效期 7 天；v1 无状态（服务端不存储），"退出登录"仅前端删 token；踢下线/黑名单是 v2 演进点（接 Redis）。
- 未登录/解析失败：拦截器直接返回 `401 + Result.error("请先登录")`（**注意：拦截器异常不走全局异常处理器**，需手写 JSON 响应）。

## 4. 统一响应

```json
{ "code": 1, "msg": "success", "data": { } }
```

- `code=1` 成功，`code=0` 业务失败（HTTP 仍 200，前端按 code 弹提示）
- 校验失败 → HTTP 400；未登录 → 401；无权限 → 403；未知异常 → 500 + `"系统繁忙，请稍后重试"`

## 5. 分页约定

- 请求：`pageNum`（默认 1）、`pageSize`（默认 10，上限 100，超出按 100）
- 响应：`PageResult{ total, rows }`（total=总记录数，rows=数据列表；`PageResult` 类在 common，随第一批分页接口一起实现）

## 6. 字段与格式约定

| 项 | 约定 | 原因 |
|---|---|---|
| 时间 | `yyyy-MM-dd HH:mm:ss` 字符串 | Jackson 全局配置 |
| 主键 id | **JSON 中一律字符串** | JS Number 超过 2^53 丢精度，雪花/大自增 id 会坑前端 |
| 金额 | JSON number，两位小数 | BigDecimal 序列化，禁止前端计算金额 |
| 枚举状态 | 返回数字 + 语义字段成对出现（如 `status: 1, statusDesc: "待支付"`） | 前端不用维护映射表 |
| DTO/VO 命名 | `XxxSaveDTO`（新增入参）/ `XxxUpdateDTO` / `XxxQueryDTO`（查询入参）/ `XxxVO`（出参） | 入参出参严格分离，防越权字段注入 |

## 7. 错误码

P1 简化为 `code=0 + msg`，不做错误码分段表（避免过早设计）；P3 接支付渠道时若需要，再引入错误码枚举。

## 8. 文档格式标准（每个接口必须完整包含以下五段）

```markdown
### N.M 接口名

#### N.M.1 基本信息
> 请求路径：/xxx
> 请求方式：GET/POST/PUT/DELETE
> 接口描述：一句话说明用途

#### N.M.2 请求参数
参数格式：application/json / queryString / 路径参数 / 无
参数说明：（表格：参数名 | 类型 | 是否必须 | 备注；嵌套对象用 |- 前缀逐行列出）
请求参数样例：（JSON 或 URL 示例；无参数则写"无"）

#### N.M.3 响应数据
参数格式：application/json
参数说明：（表格：参数名 | 类型 | 是否必须 | 备注；嵌套字段逐行 |-）
响应数据样例：（完整 JSON 示例）

#### N.M.4 备注说明
（关键校验、异常情况、技术落位）
```

**要求**：样例数据必须真实可对（id 用字符串、时间 yyyy-MM-dd HH:mm:ss、金额两位小数）；前后端以样例为联调对照物。apifox 可直接导入 Knife4j 生成的 OpenAPI JSON（/v3/api-docs）做调试与用例管理，与本文档不冲突。
