# 云票接口文档 · 07 平台端模块

> 前缀 `/admin/**`，需平台管理员鉴权（密钥 C）。审核类操作全部走条件更新 CAS + 审计日志。

## 1. 主办方入驻列表

### 1.1 基本信息

> 请求路径：/admin/merchants/page
>
> 请求方式：GET
>
> 接口描述：分页查询主办方（默认看待审核的）

### 1.2 请求参数

参数格式：queryString

参数说明：

| 参数名   | 类型   | 是否必须 | 备注                        |
| -------- | ------ | -------- | --------------------------- |
| pageNum  | number | 非必须   | 默认 1                      |
| pageSize | number | 非必须   | 默认 10                     |
| status   | number | 非必须   | 0 待审核 1 正常 2 禁用（不传查全部） |

请求参数样例：

```shell
/admin/merchants/page?status=0&pageNum=1&pageSize=10
```

### 1.3 响应数据

参数格式：application/json

参数说明：

| 参数名          | 类型      | 是否必须 | 备注             |
| --------------- | --------- | -------- | ---------------- |
| code            | number    | 必须     | 1 成功，0 失败   |
| msg             | string    | 非必须   | 提示信息         |
| data            | object    | 必须     | 分页数据         |
| \|- total       | number    | 必须     | 总记录数         |
| \|- rows        | object [] | 必须     | 数据列表         |
| \|- id          | string    | 非必须   | 主办方 id        |
| \|- name        | string    | 非必须   | 名称             |
| \|- licenseNo   | string    | 非必须   | 信用代码         |
| \|- contactName | string    | 非必须   | 联系人           |
| \|- contactPhone | string   | 非必须   | 联系电话（脱敏） |
| \|- status / statusDesc |   | 非必须   |                  |
| \|- createTime  | string    | 非必须   | 申请时间         |

响应数据样例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 2,
    "rows": [
      {
        "id": "20",
        "name": "星野演出有限公司",
        "licenseNo": "91440101MA9XXXXX0A",
        "contactName": "周经理",
        "contactPhone": "139****5678",
        "status": 0,
        "statusDesc": "待审核",
        "createTime": "2026-10-01 09:00:00"
      }
    ]
  }
}
```

### 1.4 备注说明

- 默认排序待审核优先、时间倒序（审核员的效率第一）。

## 2. 主办方入驻审核

### 2.1 基本信息

> 请求路径：/admin/merchants/{id}/audit
>
> 请求方式：POST
>
> 接口描述：通过或驳回主办方的入驻申请

### 2.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型    | 是否必须 | 备注                   |
| -------- | ------- | -------- | ---------------------- |
| approved | boolean | 必须     | true 通过 / false 驳回 |
| remark   | string  | 驳回必须 | 审核备注（驳回原因）   |

请求参数样例：

```json
{
  "approved": true,
  "remark": null
}
```

### 2.3 响应数据

参数格式：application/json

参数说明：通用 Result，data 无

响应数据样例：

```json
{ "code": 1, "msg": "success", "data": null }
```

### 2.4 备注说明

- 条件更新 CAS：`UPDATE merchant SET status=? WHERE id=? AND status=待审核`——重复点击/两个管理员并行审核只生效一次；
- 驳回必须填 remark（回显给主办方）；
- 写审计日志（MERCHANT_AUDIT）。

## 5. 演出审核

### 5.1 基本信息

> 请求路径：/admin/shows/{id}/audit
>
> 请求方式：POST
>
> 接口描述：通过或驳回演出

### 5.2 请求参数

参数格式：application/json

参数说明：

| 参数名   | 类型    | 是否必须 | 备注                   |
| -------- | ------- | -------- | ---------------------- |
| approved | boolean | 必须     | true 通过 / false 驳回 |
| remark   | string  | 驳回必须 | 审核备注               |

请求参数样例：

```json

  "remark": "票档价格明显低于成本，请说明定价依据"
```

参数格式：application/json

## 8. 主办方账户管理

> 列表复用"1. 主办方入驻列表"（`status` 不传即查全部：待审核/正常/禁用），本节只补账户处置动作。
> **禁用语义**：封的是"登录与操作能力"，不动业务数据——已销售中的演出保留销售（用户已购权益不受损），待支付订单照常走超时取消；"联动下架其全部演出"作为后续可选增强，P1 不做。

### 8.1 禁用主办方

#### 8.1.1 基本信息

> 请求路径：/admin/merchants/{id}/disable
>
> 请求方式：POST
>
> 接口描述：禁用主办方账号（正常 → 禁用），禁止其登录管理端

#### 8.1.2 请求参数

参数格式：路径参数

参数说明：

| 参数名 | 类型   | 是否必须 | 备注     |
| ------ | ------ | -------- | -------- |
| id     | string | 必须     | 主办方 id |

请求参数样例：

```
/admin/merchants/20/disable
```

#### 8.1.3 响应数据

参数格式：application/json

参数说明：通用 Result，data 无；失败原因："主办方不存在"/"当前状态不可禁用"

响应数据样例：

```json
{ "code": 1, "msg": "success", "data": null }
```

#### 8.1.4 备注说明

- 条件更新 CAS：`UPDATE merchant SET status=禁用 WHERE id=? AND status=正常`——待审核账号不能直接禁用（先走入驻审核流），已是禁用态重复禁用返回明确提示；
- 禁用后主办方**无法登录**（登录时校验 status）；
- 写审计日志（MERCHANT_DISABLE）。

### 8.2 启用主办方

#### 8.2.1 基本信息

> 请求路径：/admin/merchants/{id}/enable
>

#### 9.2 禁用用户

#### 9.2.1 基本信息

> 请求路径：/admin/users/{id}/disable
>
> 请求方式：POST
>
> 接口描述：禁用用户账号（正常 → 禁用）

#### 9.2.2 请求参数

参数格式：路径参数

参数说明：

| 参数名 | 类型   | 是否必须 | 备注   |
| ------ | ------ | -------- | ------ |
| id     | string | 必须     | 用户 id |

请求参数样例：

```

```

#### 9.2.3 响应数据

参数格式：application/json

参数说明：通用 Result，data 无；失败原因："用户不存在"/"当前状态不可禁用"

响应数据样例：

```json
{ "code": 1, "msg": "success", "data": null }
```

#### 9.2.4 备注说明

- 条件更新 CAS：`UPDATE user SET status=禁用 WHERE id=? AND status=正常`；
- **禁用生效语义（JWT 无状态的代价，诚实标注）**：v1 的 JWT 不受服务端控制，已签发 token 无法立即作废。落地策略：**登录时拦截**（禁用后无法再登录）+ **关键写接口（下单/支付）校验用户 status**（主键单行查询，代价可忽略），读接口容忍 token 自然过期前的延迟；v2 演进为 Redis 黑名单（禁用时拉黑 userId，拦截器统一校验）实现立即失效——标准的"无状态→有状态演进"面试素材；
- **禁用不影响资金与已购权益**：待支付订单照常走超时取消，已出票的票照常有效可核销（核销是主办方侧操作）；
- 写审计日志（USER_DISABLE）。
