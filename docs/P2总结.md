## 二、关键决策（面试必问"为什么"）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **Redisson 替换 Lettuce** | 需要 RLock/RBloomFilter 开箱即用；`RedisTemplate` 仍可用（Redisson 提供 ConnectionFactory）|
| 2 | **key 用 String，value 用 JSON** | key 可读便于排查；JSON 可读/跨语言/体积小 |
| 3 | **value 带 `@class`** | 反序列化才知道还原成什么类型（`GenericJackson2JsonRedisSerializer` 自动写）|
| 4 | **独立 ObjectMapper**（不注入全局）| 全局 mapper 上加 default typing 会让 HTTP 响应也冒出 `@class` → 污染契约 |
| 5 | **必须注册 JavaTimeModule** | Redis 序列化器自带的 mapper 不认识 `LocalDateTime` → 缓存详情直接报错 |
| 6 | **列表单级、详情多级** | 列表每页 10 条 × 组合多 × TTL 30s 短 → 本地命中率低；详情单条热点 → 本地收益高 |
| 7 | **keyword 不缓存** | 无限组合/长尾，缓存只会生产废 key；P6 交 ES |
| 8 | **逻辑过期 30m + 物理 TTL 60m** | 物理必须比逻辑长，否则 key 被 Redis 删掉，逻辑过期退化成物理过期（阻塞）|
| 9 | **抢到锁返回新值、没抢到返回旧值** | 同步重建后返回旧值 = 让用户白等；抢到锁的反正查了库，直接给新值 |
| 10 | **主动失效"先改库再删缓存"** | 先删后改：窗口期内并发读会把旧值回填（脏）；删是幂等安全的，更新缓存不安全 |
| 11 | **热榜滑动窗口** | 只查当天会凌晨空榜/波动大；`ZUNIONSTORE` 合并近 7 天 = 累计 + 新鲜（老热度自然滑出）|
| 12 | **虚拟线程后瓶颈转移** | 线程不再是上限 → Hikari 10 连接成为新瓶颈（P3 前要调大）|

## 四、踩坑记录（8 个，面试可讲"你遇到过什么难题"）

| # | 坑 | 解法 |
|---|---|---|
| 1 | `GenericJackson2JsonRedisSerializer` 默认 mapper 不支持 `LocalDateTime` | 注册 `JavaTimeModule` + 关时间戳 |
| 2 | `lock.isLocked()` 当成"抢锁"用 | 用 `tryLock()`；`isLocked` 只查占用，非持有者 unlock 会抛异常 |
| 3 | 逻辑过期重建后返回旧值 | 抢到锁的返回新值 |
| 4 | `ValueOperations.get()` 返回 `Object`，强转泛型告警 | `@SuppressWarnings("unchecked")`（类型安全靠 key 规范）|
| 5 | Caffeine 的 `Cache` 与 Spring 的 `Cache` 同名不同包 | import `com.github.benmanes.caffeine.cache.Cache` |
| 6 | 造数据 `category_id` 与票档 id 错位 → 余量恒 0 | `INSERT ... SELECT JOIN` 重建（1200 行）|
| 7 | **JMeter GUI 压不出真实 QPS**（~1000 上限）| 命令行 `java -jar ApacheJMeter.jar -n` |
| 8 | 日志文件位置随启动方式变（命令行=模块目录，IDEA=项目根）| 统一工作目录或记住两处 |

## 五、简历文案（3 条，可直接用）

1. **多级缓存改造**：为演出列表/详情/余量设计分层缓存策略（列表：结果缓存 + TTL 抖动；详情：Caffeine + Redis 逻辑过期 + RLock 互斥重建 + 布隆防穿透），列表接口 QPS 提升 **161%**、P95 降低 **95%**；详情单次命中耗时从 210ms 降至 **3.7ms**。
2. **缓存三件套防护**：布隆过滤器（Redis 预热度 301 条）+ 空值缓存防穿透；逻辑过期 + 分布式锁互斥重建防击穿（100 并发仅回源 2 次）；TTL 随机抖动 + 多级缓存防雪崩；写操作主动失效（编辑/下架/审核）保证缓存一致性。
3. **可观测与性能调优**：接入 traceId 链路追踪（Filter + MDC，响应头透传）+ 慢接口 AOP 告警（>200ms）+ 日志落盘滚动；开启虚拟线程后详情接口平均耗时 **40→12ms（-70%）**、长尾 **496→96ms（-81%）**。
